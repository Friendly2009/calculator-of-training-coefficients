# Переработать интерфейс калькулятора и исправить расчёт, состояние и навигацию

## Задача

Объединить четыре подготовленных патча в одно изменение: исправить ошибки калькулятора и заменить сетку из 20 кнопок интерфейсом «выбор коэффициента → четыре кнопки оценок».

Репозиторий: [Friendly2009/calculator-of-training-coefficients](https://github.com/Friendly2009/calculator-of-training-coefficients).

База серии — ветка `master`, коммит `206978ae698821a678442e837cba5ef27f72e29e`. В этой версии репозитория ветки `main` нет. Каждый патч создаёт отдельный коммит; применять их нужно последовательно.

## Проблемы исходной версии

- Результат не обновлялся после добавления или удаления оценки. После удаления всех записей повторный расчёт оставлял прежнее число.
- Кнопка возврата из поддержки создавала новый экран калькулятора вместо возврата к существующему.
- Текущий расчёт не восстанавливался после уничтожения процесса системой.
- Нажатие на оценку сразу удаляло её; явного действия и отмены не было.
- Логика не проверяла допустимость оценок и коэффициентов.
- README обещал произвольные коэффициенты, но интерфейс предоставлял только фиксированные значения.
- Экран был перегружен одинаковыми кнопками, использовал мелкие подписи и фиксированные размеры без вертикальной прокрутки и полноценного учёта системных отступов.
- Версии Kotlin/Compose Compiler и Lifecycle требовали согласования; содержательных тестов не было.

## Ожидаемое поведение

- Средний балл автоматически меняется после добавления, редактирования, удаления и отмены удаления. Пустой список показывает `—`.
- Допустимы целые оценки от 2 до 5 и конечный коэффициент больше 0 и не больше 1000. При вводе коэффициента принимаются точка и запятая.
- Выбранный коэффициент используется для следующих добавлений, пока пользователь его не изменит.
- Формула: `Σ(оценка × коэффициент) / Σ(коэффициентов)`. Промежуточные результаты не округляются; отображение округляется до двух знаков по правилу `HALF_UP`.
- Возврат из поддержки сохраняет расчёт и не добавляет новый экран в стек.
- Очистка требует подтверждения. Последнее удаление или очистку можно временно отменить, сохранив последующие добавления.
- Максимум — 500 оценок. Если отмена превысит лимит, приложение показывает сообщение и не отбрасывает записи молча.
- Текущий расчёт восстанавливается при пересоздании Activity или восстановлении Android-задачи после уничтожения процесса. Постоянная история расчётов в эту задачу не входит.

## Применение серии

При чистом рабочем дереве, если файлы патчей находятся в корне репозитория:

```bash
git switch -c fix/calculator-redesign 206978a
git am ./0001-build.patch ./0002-calculation-state.patch ./0003-interface.patch ./0004-readme-ci.patch
```

`git am` создаст четыре коммита. Эти два Markdown-описания предназначены для issue и релиза и не являются дополнительными патчами серии.
